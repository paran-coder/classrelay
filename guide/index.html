Google Cloud 프로젝트
ClassRelay용 Google 설정을 모아두는 하나의 작업 상자라고 생각하시면 됩니다. Forms API, Gmail API, OAuth 설정을 이 프로젝트 안에 만듭니다.
API
ClassRelay가 Google Form이나 Gmail과 대화할 수 있게 해주는 기능입니다. 이 가이드에서는 Google Forms API와 Gmail API 두 개를 켭니다.
OAuth Client ID
ClassRelay가 “이 Google 계정의 권한을 사용해도 되나요?”라고 요청할 때 사용하는 연결 ID입니다. 비밀번호가 아닙니다.
Test user
Google OAuth 앱이 아직 Testing 상태일 때 사용할 수 있도록 미리 허용해 둔 Google 계정입니다. 본인 Gmail을 등록하면 됩니다.
중요한 원칙 · ClassRelay 운영자가 공용 Google 계정을 주는 구조가 아닙니다. 각 사용자가 본인의 Google Cloud 프로젝트와 Client ID를 직접 만들고 본인의 Form과 Gmail을 연결합니다.
Google Cloud가 너무 낯설다면 · 아래 1~3장을 한 번에 끝내는 것을 권장합니다. 중간에 브라우저를 닫아도 설정은 Google 계정에 저장되지만, 어느 프로젝트에서 작업했는지 헷갈리기 쉽습니다.
처음 한 번 · Google Cloud

1. ClassRelay용 Google Cloud 프로젝트 만들기

지금부터 Google Cloud에서 설정합니다. 비용 결제 화면을 설정할 필요는 없습니다. ClassRelay에 필요한 것은 프로젝트, Forms API, Gmail API, Google Auth Platform입니다.

1

Google Cloud의 새 프로젝트 화면을 엽니다.

아래 버튼을 누르면 Google Cloud Console의 새 프로젝트 화면으로 이동합니다. Google 로그인이 필요하면 ClassRelay에서 사용할 Google 계정으로 로그인하세요.

Google Cloud 새 프로젝트 열기 ↗

  1. 프로젝트 이름(Project name)에 ClassRelay라고 입력합니다.
  2. 개인 Google 계정이라면 조직/위치 항목이 없거나 선택할 것이 없을 수 있습니다. 그대로 두셔도 됩니다.
  3. 만들기(Create)를 누릅니다.
  4. 생성이 끝나면 화면 위쪽 프로젝트 선택기를 눌러 방금 만든 ClassRelay 프로젝트가 선택되어 있는지 확인합니다.
이렇게 보이면 성공입니다.Google Cloud 화면 위쪽 프로젝트 이름이 ClassRelay로 표시됩니다.
가장 흔한 실수 · 프로젝트를 만든 뒤 다른 프로젝트가 선택된 상태에서 API를 켜는 것입니다. 다음 단계로 갈 때마다 화면 위쪽 프로젝트 이름이 ClassRelay인지 확인하세요.
2

Google Forms API를 켭니다.

이 기능이 켜져 있어야 ClassRelay가 Form 제목, 질문, 신청 응답을 읽을 수 있습니다.

Google Cloud→API 및 서비스→라이브러리→Google Forms API

Google Forms API 바로 열기 ↗

  1. 화면 위쪽 프로젝트가 ClassRelay인지 확인합니다.
  2. 사용(Enable) 또는 사용 설정 버튼을 누릅니다.
  3. 버튼이 사라지고 API 관리 화면이 보이면 완료입니다.
완료 기준Google Forms API가 사용 설정된 상태입니다.
3

Gmail API도 같은 방식으로 켭니다.

ClassRelay가 본인의 Gmail 계정으로 강의 안내메일이나 녹화본 메일을 보낼 때 사용합니다.

Gmail API 바로 열기 ↗

  1. 프로젝트가 ClassRelay인지 다시 확인합니다.
  2. 사용(Enable)을 누릅니다.
완료 기준Forms API와 Gmail API 두 개가 모두 켜져 있습니다.

Google 공식 안내: Google Workspace API 사용 설정 ↗

처음 한 번 · Google Auth Platform

2. Google이 ClassRelay 연결을 허용하도록 설정하기

이 부분이 처음 사용자에게 가장 어렵습니다. 아래 순서대로 Branding → Audience → Data Access → Clients를 차례로 설정하면 됩니다.

1

Google Auth Platform을 처음 설정합니다.

아래 버튼을 누른 뒤, 아직 설정하지 않았다면 시작하기(Get started)가 보입니다.

Google Auth Platform 열기 ↗

  1. 시작하기(Get started)를 누릅니다.
  2. 앱 이름(App name)에 ClassRelay를 입력합니다.
  3. 사용자 지원 이메일(User support email)에서 본인 이메일을 선택합니다.
  4. 다음(Next)을 누릅니다.
  5. 대상(Audience)에서 개인 Gmail을 쓰는 경우 외부(External)를 선택합니다. 일반적인 ClassRelay 개인 사용자는 이 항목을 선택하면 됩니다. 내부(Internal)는 회사·학교 Google Workspace 조직 안의 사용자만 사용할 때 선택합니다.
  6. 외부(External)를 선택했으면 화면 아래의 다음(Next)을 눌러 다음 단계로 이동합니다.
  7. 연락처 이메일(Contact information)에 본인 이메일을 입력합니다.
  8. Google API Services User Data Policy 확인 항목에 동의하고 계속(Continue) → 만들기(Create)를 누릅니다.
이렇게 보이면 성공입니다.왼쪽 Google Auth Platform 메뉴에 Branding, Audience, Data Access, Clients가 보입니다.
2

필수 · Audience에서 본인 Gmail을 Test user로 반드시 추가합니다.

이 단계는 필수입니다. Testing 상태인데 본인 계정이 Test users에 없으면 Google 로그인 과정에서 403 access_denied가 발생할 수 있습니다.
Google 인증 플랫폼→대상(Audience)→화면 아래 테스트 사용자(Test users)→+ Add users
  1. 왼쪽 메뉴에서 대상(Audience)을 누릅니다.
  2. 페이지를 아래로 내려 테스트 사용자(Test users) 영역을 찾습니다.
  3. + Add users / 사용자 추가를 누릅니다.
  4. ClassRelay에서 실제로 Google Form과 Gmail에 사용할 본인 Gmail 주소를 입력합니다. 본인 계정 하나만 테스트할 예정이라면 한 개만 추가해도 됩니다.
  5. 오른쪽 패널의 저장(Save)을 누릅니다.
완료 기준Test users 목록에 ClassRelay에서 로그인할 본인 Gmail이 보입니다.
Google 계정이 여러 개 로그인되어 있다면 · 나중에 권한창에서도 여기 Test users에 넣은 계정을 선택해야 합니다.
3

Data Access에서 ClassRelay가 사용할 권한 3개를 직접 추가합니다.

여기서는 아래 값을 웹 링크처럼 클릭하는 것이 아닙니다. 범위 직접 추가(Manually add scopes) 입력칸에 scope 문자열을 그대로 복사해 붙여넣습니다.

Google 인증 플랫폼→데이터 액세스(Data Access)→범위 추가 또는 삭제(Add or remove scopes)→범위 직접 추가(Manually add scopes)
  1. 왼쪽 메뉴에서 데이터 액세스(Data Access)를 누릅니다.
  2. 범위 추가 또는 삭제(Add or remove scopes)를 누릅니다.
  3. 범위 직접 추가(Manually add scopes) 영역을 찾습니다.
  4. 아래 scope 세 개를 복사해 입력한 뒤 Add to Table을 눌러 표에 추가합니다.
  5. 세 항목이 표에 들어간 것을 확인한 뒤 Update / 업데이트를 누릅니다.
  6. 원래 Data Access 화면으로 돌아오면 Save / 저장까지 눌러 완료합니다.
아래 값은 클릭하는 링크가 아닙니다.복사 버튼으로 문자열을 복사한 뒤 Google의 범위 직접 추가 입력칸에 붙여넣으세요.
Form 내용 읽기
https://www.googleapis.com/auth/forms.body.readonly
Form 응답 읽기
https://www.googleapis.com/auth/forms.responses.readonly
Gmail 발송
https://www.googleapis.com/auth/gmail.send
완료 기준Data Access의 권한 목록에서 위 세 scope를 확인할 수 있습니다.

4

Clients에서 Web application Client ID를 만듭니다.

Google Auth Platform→Clients→Create client

OAuth Clients 열기 ↗

  1. Create client / 클라이언트 만들기를 누릅니다.
  2. Application type에서 Web application을 선택합니다.
  3. 이름은 ClassRelay Web처럼 알아보기 쉽게 입력합니다.
  4. Authorized JavaScript origins 영역에서 Add URI를 누릅니다.
  5. 아래에 표시되는 ClassRelay 주소를 그대로 넣습니다. /guide 같은 뒷부분은 넣지 않습니다.
  6. Authorized redirect URIs는 비워둡니다. ClassRelay는 서버 callback 방식이 아닙니다.
  7. Create / 만들기를 누릅니다.
  8. OAuth 클라이언트 생성됨 팝업이 나타나면 ...apps.googleusercontent.com 형태의 클라이언트 ID를 확인하고 필요하면 오른쪽 복사 아이콘으로 복사합니다.
  9. 팝업 오른쪽 아래의 확인을 눌러 닫습니다.
Client Secret은 사용하지 않습니다. 생성 팝업에 클라이언트 보안 비밀번호(Client secret)가 함께 보여도 ClassRelay에는 입력하지 않습니다. ClassRelay에 필요한 값은 Client ID뿐입니다.
AUTHORIZED JAVASCRIPT ORIGIN · 그대로 복사

완료 기준...apps.googleusercontent.com 형태의 Client ID가 만들어졌고 생성 완료 팝업에서 확인을 눌렀습니다.

Google 공식 안내: Web Client ID 설정 ↗

5

Client ID만 복사합니다. Client Secret은 사용하지 않습니다.

Google이 보여주는 값 중 ClassRelay에 필요한 것은 ...apps.googleusercontent.com로 끝나는 Client ID입니다.

Client Secret은 ClassRelay에 입력하지 않습니다. 이 앱은 브라우저 Token Model을 사용하기 때문에 Client Secret을 요구하거나 저장하지 않습니다.
여기까지 Google Cloud 설정 완료Client ID를 복사해 두셨다면 이제 ClassRelay로 돌아오시면 됩니다.
ClassRelay로 돌아오기

3. 만든 Client ID를 ClassRelay에 연결하기

Google Cloud 설정은 끝났습니다. 이제 ClassRelay 설정 화면에 방금 만든 Client ID를 한 번 저장합니다.

1

ClassRelay 왼쪽 메뉴에서 설정을 누릅니다.

ClassRelay→왼쪽 메뉴 설정→1. Google OAuth

ClassRelay 설정 열기 →

  1. OAuth Client ID 입력칸을 찾습니다.
  2. Google Cloud에서 복사한 ...apps.googleusercontent.com 값을 붙여넣습니다.
  3. 저장을 누릅니다.
완료 기준Google OAuth 카드 오른쪽 상태가 저장됨으로 바뀝니다.
설정 화면에 보이는 Origin 복사 버튼 · 이 값은 앞 단계의 Authorized JavaScript origins에 넣는 주소와 같은 값입니다.
2

처음 Google 연결 화면이 나오면 Test user로 등록한 본인 계정으로 계속 진행합니다.

Form 연결이나 Gmail 권한 확인을 처음 실행하면 Google 계정 선택, 테스트 앱 경고, 권한 선택 화면이 차례로 나타날 수 있습니다.

  1. Google 계정 선택 화면이 나오면 앞에서 Test users에 등록한 본인 Gmail을 선택합니다.
  2. Google에서 확인하지 않은 앱 화면이 나오면 현재 앱이 본인이 만든 테스트 OAuth 앱이고 로그인 계정이 Test user로 등록한 본인 계정인지 다시 확인합니다.
  3. 확인했다면 왼쪽 아래의 계속을 누릅니다. 안전한 환경으로 돌아가기를 누르면 연결 과정이 중단됩니다.
  4. classrelay.vercel.app에서 Google 계정에 대한 액세스를 요청합니다 화면에서는 모두 선택을 체크하거나 아래 두 Forms 권한을 각각 선택합니다: Google Forms 양식의 모든 응답 확인, 모든 Google Forms 양식 확인.
  5. 권한을 선택한 뒤 화면 아래로 내려 계속을 누릅니다.
  6. 이후 Google 계정 선택 화면이 다시 나타나면 앞에서 Test user로 등록한 같은 본인 Gmail을 선택합니다.
왜 Forms 권한이 두 개인가요? 하나는 Form의 제목·질문 구조를 읽고, 다른 하나는 제출된 응답을 읽기 위한 권한입니다. ClassRelay는 Form을 수정하거나 삭제하는 권한을 요청하지 않습니다.
403 access_denied가 나오면 · Client ID를 다시 만들기 전에 먼저 Google 인증 플랫폼 → 대상(Audience) → 테스트 사용자(Test users)에 현재 선택한 계정이 등록되어 있는지 확인하세요.
강의마다 한 번

4. 강의를 만들고 Google Form을 연결하기

ClassRelay는 강의가 중심입니다. 강의 하나에 신청 Form 하나를 연결하고, 그 강의의 신청·입금·메일·CS 히스토리를 계속 누적합니다. Google Drive 전체 파일 목록 권한을 요청하지 않기 때문에 계정의 Form 목록을 자동으로 훑지 않고, 사용할 Form의 편집 URL을 직접 연결합니다.

1

먼저 ClassRelay에서 강의를 만듭니다.

왼쪽 메뉴→강의 관리→강의 추가
  1. 강의명을 입력합니다. 예: ChatGPT 업무자동화 9월반
  2. 가격을 숫자로 입력합니다. 예: 39000
  3. 상태는 처음에는 사용으로 둡니다.
  4. 녹화본 URL (선택)은 지금 없어도 됩니다. 녹화가 끝난 뒤 나중에 강의 편집에서 추가할 수 있습니다.
  5. 저장을 누릅니다.
완료 기준강의명과 가격만으로도 저장되고, 강의 관리 목록에 방금 만든 강의가 보입니다.
YouTube를 사용하는 경우 · ClassRelay는 YouTube API를 사용하지 않습니다. 사용자가 입력한 URL을 메일에 넣어 전달합니다. 일부공개 영상은 링크를 가진 사람이 다시 공유할 수 있습니다. 비공개 영상은 허용된 사용자만 볼 수 있어 단순 URL 발송과는 사용 방식이 다릅니다.

신청용 Google Form이 없다면 하나 만듭니다.

5. Form 신청자를 ClassRelay로 가져오기

Form에 신청이 들어와도 ClassRelay가 브라우저를 닫은 동안 자동 감시하지는 않습니다. 운영할 때 동기화 버튼을 눌러 새 신청을 확인합니다.

1

여러 강의를 운영한다면 대시보드의 전체 폼 동기화를 누릅니다.

대시보드→전체 폼 동기화

사용 중인 강의에 연결된 모든 활성 Form을 차례로 확인합니다.

정상 결과“Form n개 · 신규 n건 · 기존 n건 확인”과 같은 완료 안내가 표시됩니다.
2

한 강의만 확인하고 싶다면 이 강의 폼 동기화를 사용합니다.

강의 관리→해당 강의 히스토리→이 강의 폼 동기화
기존 기록은 초기화되지 않습니다. · 같은 Form 응답을 다시 읽어도 response ID를 기준으로 기존 신청 건과 병합하므로 기존 입금확인, 발송일, 발송횟수, CS 메모는 유지됩니다.
운영할 때 반복 · 은행 입금내역

6. 은행 입금내역을 가져와 입금 확인하기

은행에서 내려받은 CSV/TSV 또는 Excel 97-2003 .xls 파일을 ClassRelay가 브라우저 안에서 읽습니다. 파일 자체를 ClassRelay 서버에 업로드하지 않습니다.

1

처음 쓰는 파일 형식은 은행 내역 템플릿을 한 번 만듭니다.

입금 관리→은행 내역 가져오기→새 템플릿 만들기
  1. 은행에서 내려받은 실제 입금내역 파일을 하나 선택합니다.
  2. ClassRelay가 파일에서 표를 읽으면 열 이름이 적힌 헤더 행을 선택합니다.
  3. 입금 날짜, 입금자명, 입금액 열을 지정합니다.
  4. 신한은행처럼 날짜와 시간이 다른 열이면 입금 시간도 선택합니다.
  5. 은행 고유번호나 참조번호 열이 있으면 은행 고유번호에 선택합니다. 없으면 `사용 안 함`으로 둬도 됩니다.
헤더 행이란? · `입금일시 · 입금자명 · 입금액`처럼 각 열의 이름이 적혀 있는 줄입니다. 은행 파일 위쪽에 계좌정보나 조회기간이 몇 줄 먼저 있어도 실제 열 이름이 시작되는 행을 선택하면 됩니다.
2

5행 미리보기를 확인하고 원하는 이름으로 저장합니다.

열을 지정하면 ClassRelay가 실제로 사용할 값만 정리한 미리보기를 최대 5행 보여줍니다. 입금일시, 입금자명, 입금액이 올바르게 읽히는지 확인하세요.

  1. 미리보기의 이름과 금액이 원본 파일과 맞는지 확인합니다.
  2. 템플릿 이름에 알아보기 쉬운 이름을 입력합니다. 예: KB 개인계좌, 신한 강의계좌.
  3. 템플릿 저장 + 가져오기를 누릅니다.
정상 결과템플릿이 브라우저에 저장되고, 샘플에 실제 입금 행이 있으면 같은 파일의 신규 입금이 누적된 뒤 자동매칭 결과가 표시됩니다.
입금 행이 없는 빈 샘플도 저장할 수 있습니다. · 헤더와 열만 있는 파일이라면 템플릿만 저장합니다. 이후 첫 실제 입금 파일을 올렸을 때 ClassRelay가 5행 미리보기를 한 번 보여주며, 값을 확인한 뒤 가져옵니다.
템플릿은 은행명에 고정되지 않습니다. · 같은 은행에서도 개인계좌/사업자계좌처럼 파일 구조가 다르면 별도 이름으로 저장할 수 있습니다.
3

다음부터는 저장한 템플릿을 선택하고 파일만 넣습니다.

입금 관리→은행 내역 가져오기→저장된 템플릿 선택→새 입금내역 파일 선택

저장할 때와 열 구조가 같으면 ClassRelay가 구조를 확인한 뒤 바로 신규 입금을 가져오고 자동매칭합니다. 열 위치가 바뀌었다면 조용히 잘못 읽지 않고 새 템플릿을 만들도록 안내합니다.

같은 파일을 다시 올려도 기존 입금과 발송 기록을 지우지 않고 이미 가져온 항목은 중복 방지 규칙으로 건너뜁니다.
4

자동확인과 확인필요의 차이를 이해합니다.

ClassRelay는 잘못된 자동확정을 줄이기 위해 보수적으로 판단합니다.

상태뜻내가 할 일
입금확인정규화한 입금자명 + 금액 + 입금일 범위가 맞고 후보가 1:1로 유일함별도 확인 없이 발송 준비 가능
확인필요동명이인, 중복 후보, 비슷한 이름 등 자동확정하기 애매함신청자 상세에서 직접 확인 후 연결
입금대기아직 맞는 입금을 찾지 못함추가 입금내역을 넣거나 입금을 기다림
기본 자동매칭 기간 · 신청일 기준 1일 전부터 7일 후까지의 입금을 후보로 봅니다. 설정에서 변경할 수 있습니다.
5

확장자는 .xls인데 파일 안에 표가 없는 경우도 있습니다.

일부 은행은 .xls 파일 안에 실제 표를 넣지 않고 별도의 *.files/sheet001.htm 파일을 가리키는 HTML 형식으로 내보내기도 합니다. ClassRelay가 이 형식을 발견하면 임의로 잘못 읽지 않고 “파일 안에 실제 표가 없다”는 안내를 표시합니다.

이 경우 · 은행에서 CSV나 실제 표가 포함된 .xls 다운로드 옵션이 있는지 확인하세요. 다른 형식이 전혀 없다면 해당 파일을 Excel/한셀에서 열었을 때 내역이 보이는 경우 CSV로 다시 저장한 뒤 ClassRelay에 넣을 수 있습니다. 단일 파일 안에 입금 데이터가 존재하지 않으면 브라우저 앱이 그 데이터를 스스로 복원할 수는 없습니다.
운영할 때 반복 · Gmail

7. 메일 템플릿을 만들고 강의 메일 보내기

ClassRelay는 한 번의 발송 작업에는 한 강의만 포함합니다. 먼저 강의를 확정하고, 그 강의에서 실제로 발송 가능한 신청자만 선택합니다.

1

메일 템플릿을 준비합니다.

왼쪽 메뉴→메일 / 발송로그
  1. 처음이라면 기본 템플릿의 제목과 본문을 원하는 문구로 수정합니다.
  2. 새 문구가 필요하면 + 템플릿 추가를 누릅니다.
  3. 기존 문구를 조금만 바꿔 쓰려면 복제를 사용합니다.
  4. 특정 강의에만 다른 문구를 쓰고 싶으면 그 템플릿의 사용 강의에서 강의를 연결합니다.
사용 가능한 변수 · {{이름}}, {{강의명}}, {{녹화본URL}}, {{신청번호}}, {{금액}}
{{녹화본URL}}을 제목이나 본문에서 쓰지 않으면 강의에 녹화본 URL이 없어도 메일을 보낼 수 있습니다.
2

처음 한 번 Gmail 권한 확인을 해봅니다.

메일 / 발송로그→Gmail 권한 확인
  1. Google 계정 선택창에서 Test user로 등록한 계정을 선택합니다.
  2. 메일 발송 권한을 허용합니다.
완료 기준Gmail 권한 오류 없이 ClassRelay 화면으로 돌아옵니다.
받은편지함을 읽는 권한은 사용하지 않습니다. ClassRelay의 Gmail 권한은 gmail.send, 즉 메일 발송용입니다.
3

발송 대상 선택을 눌러 먼저 강의를 고릅니다.

메일 / 발송로그→발송 대상 선택→강의 선택

각 강의 옆에 발송 가능 n명이 표시됩니다. 입금확인, 이메일 정상, 메일 템플릿, 기존 발송 상태 등 필요한 조건을 만족한 신청 건만 발송 가능으로 계산됩니다. {{녹화본URL}}을 사용하는 템플릿이라면 그때만 녹화본 URL도 필요합니다.

강의 히스토리에서 시작할 수도 있습니다. · 해당 강의 화면의 이 강의 발송 대상 n명을 누르면 강의 선택 단계를 건너뜁니다.
4

발송할 사람을 체크하고 선택 발송을 누릅니다.

현재 선택한 강의의 발송 가능한 신청자만 보입니다. 다른 강의 신청자는 섞이지 않습니다.

  1. 보낼 신청자를 체크합니다.
  2. 선택 발송을 누릅니다.
  3. 최종 확인창에서 강의명, 인원, 템플릿, 제목이 맞는지 확인합니다. 녹화본 URL을 쓰는 템플릿이면 URL도 함께 확인합니다.
  4. 맞다면 발송 버튼을 누릅니다.
처음 실제 테스트는 본인 이메일 1건으로 권장합니다. 여러 명에게 보내기 전에 제목과 본문이 실제 메일에서 올바르게 보이는지 먼저 확인하세요. 녹화본 URL을 사용하는 메일이면 링크도 확인합니다.
5

발송 결과를 확인합니다.

메일 / 발송로그의 하단 전체 폭 발송 내역 테이블에서 발송 시각, 신청자, 강의, 템플릿, 동작을 확인할 수 있습니다. 발송 내용 보기를 누르면 그때 실제로 보낸 제목·본문과 녹화본 URL(사용한 경우)도 확인할 수 있습니다.

발송 확인 필요가 뜨면 바로 다시 보내지 마세요. 네트워크가 끊겼지만 Gmail 쪽에서는 이미 보냈을 가능성이 있습니다. 실제 수신 여부를 확인한 뒤 재발송하세요.
나중에 문의가 왔을 때

8. “녹화본을 못 받았어요” CS 처리하기

ClassRelay는 지금 발송하는 기능만이 아니라 과거 강의의 신청·입금·발송 기록을 확인하는 용도로도 사용합니다.

1

해당 강의를 찾아 히스토리를 엽니다.

강의 관리→과거 강의→히스토리
  1. 고객 이름, 이메일, 입금자명으로 검색합니다.
  2. 신청자 행을 클릭하면 오른쪽 CS 패널이 해당 신청자로 바뀝니다.
  3. 입금 상태, 최종 발송일, 발송 횟수, Gmail Message ID, 활동 로그를 확인합니다.
  4. 필요하면 CS 메모를 남기고 재발송합니다.
Form을 다시 동기화해도 과거 발송횟수나 CS 메모가 초기화되지 않습니다.
데이터 보호

9. 백업은 꼭 주기적으로 해두세요.

ClassRelay는 중앙 DB가 아니라 현재 브라우저에 데이터를 저장합니다. 브라우저 데이터를 직접 삭제하거나 PC를 바꾸면 기존 데이터가 자동으로 따라가지 않습니다.

1

설정에서 백업 내보내기를 누릅니다.

설정→4. 로컬 데이터 관리→백업 내보내기

강의, Form 연결, 신청자, 입금, 은행 내역 템플릿, 메일 템플릿, 발송로그, CS 기록이 JSON 파일 하나에 저장됩니다.

백업 파일에는 개인정보가 들어갈 수 있습니다. 공개 드라이브, 공개 GitHub, 여러 사람이 보는 폴더에는 올리지 마세요.

새 PC에서는 백업 불러오기를 사용합니다.

10. 실제 고객에게 보내기 전에 본인 이메일로 한 번 연습하세요.

아래 실습을 통과하면 Google 연결, Form 동기화, 입금 매칭, Gmail 발송까지 핵심 기능을 한 번씩 실제로 확인한 것입니다.

30분 안에 끝내는 전체 테스트

실제 운영 데이터와 섞이지 않도록 가능하면 운영을 시작하기 전에 진행하세요.

1. 강의 관리에서 ClassRelay 테스트 강의를 만들고 가격을 1000으로 입력합니다. 녹화본 URL은 비워둔 채 시작해도 됩니다. 일반 안내메일 테스트를 먼저 해볼 수 있습니다.
2. Google Form을 하나 만들고 이름, 입금자명, 이메일 질문을 추가합니다.
3. Form을 직접 한 번 제출합니다. 이메일은 반드시 본인 이메일을 넣습니다.
4. ClassRelay에서 테스트 강의와 Form을 연결하고 이 강의 폼 동기화를 실행합니다.
5. 신청자 목록에 방금 입력한 본인이 보이는지 확인합니다.
6. 테스트용 CSV를 직접 만들어도 됩니다. 첫 줄에 입금일시,입금자명,입금액을 쓰고, 둘째 줄에 오늘 날짜·Form에 입력한 입금자명·1000을 입력한 뒤 CSV로 저장합니다.
7. 입금 관리 → 은행 내역 가져오기 → 새 템플릿 만들기에서 테스트 CSV를 넣고, 헤더 1행과 세 열을 지정해 템플릿을 저장한 뒤 신청자가 입금확인으로 바뀌는지 봅니다.
8. 메일 템플릿 제목과 본문을 테스트용으로 작성합니다.
9. 메일 / 발송로그 → 발송 대상 선택 → 테스트 강의 → 본인 신청 건 선택 → 최종 확인 → 발송합니다.
10. 실제 Gmail 받은편지함에서 제목·본문이 맞는지 확인하고, ClassRelay 발송로그에서 발송 내용 보기도 확인합니다.
최종 합격 기준 · Form 신청 1건이 올바른 강의에 들어오고 → 은행 입금내역 한 건과 자동매칭되고 → 본인 Gmail로 올바른 강의 안내메일이 도착하고 → 발송로그에 당시 내용이 남으면 기본 운영 흐름은 정상입니다.
테스트 후 로컬 데이터 전체 삭제는 신중하게 · 이미 실제 운영 데이터를 넣은 상태에서는 “모든 로컬 데이터 삭제”를 사용하지 마세요. 테스트와 실제 데이터를 섞기 전에 먼저 백업하는 것이 안전합니다.
문제 해결

막혔을 때는 오류 문구에 맞는 항목부터 보세요.

처음 설정에서 발생하는 문제는 대부분 Google Cloud 프로젝트 선택, Test user, API 사용 설정, URL 종류 중 하나입니다.

Google 로그인에서 `403 access_denied`가 나옵니다.

Google Auth Platform → Audience → Test users에 현재 로그인하려는 Gmail이 들어 있는지 먼저 확인하세요. Testing 상태에서는 등록되지 않은 계정이 차단될 수 있습니다. 여러 Google 계정이 로그인되어 있다면 권한창에서 Test users에 넣은 계정을 선택했는지도 확인합니다.

`origin_mismatch` 또는 OAuth Client 관련 오류가 납니다.

Google Auth Platform → Clients → ClassRelay Web을 열고 Authorized JavaScript origins에 현재 ClassRelay 도메인이 정확히 들어 있는지 확인합니다. /guide나 /#settings 같은 경로를 붙이지 않습니다. 현재 이 사이트에서 복사해야 하는 origin은 입니다.

Form URL이 잘못되었다고 나옵니다.

forms.gle 축약 주소나 /viewform 응답자 주소가 아니라, 질문을 수정할 수 있는 편집 화면의 긴 주소를 사용하세요. 지원 예시는 https://docs.google.com/forms/u/0/d/FORM_ID/edit 입니다.

Google Forms API 또는 Gmail API가 비활성화됐다고 나옵니다.

Google Cloud 화면 위쪽 프로젝트가 ClassRelay 프로젝트인지 확인한 뒤 Forms API와 Gmail API가 각각 Enabled인지 확인합니다. 다른 프로젝트에서 API를 켠 경우 현재 Client ID에는 적용되지 않습니다.

Form을 읽었는데 질문 매핑이 이상합니다.

자동 추천은 질문 제목을 보고 추정합니다. 이름, 입금자명, 이메일, 연락처를 드롭다운에서 직접 지정하세요. 결제금액 매핑은 없으며 신청 당시 강의 가격이 자동 저장됩니다. 강의도 Form 질문이 아니라 Form에 연결한 ClassRelay 강의로 고정됩니다.

Form에 신청했는데 신청자 목록에 바로 안 보입니다.

ClassRelay는 브라우저를 닫은 동안 자동 감시하지 않습니다. 대시보드의 전체 폼 동기화 또는 강의 히스토리의 이 강의 폼 동기화를 실행하세요.

은행 내역을 넣었는데 입금확인이 안 됩니다.

처음 만든 템플릿의 입금자명 열과 입금액 열이 정확한지 먼저 확인하세요. 이름이나 금액이 다르거나, 신청일 기준 허용 기간 밖의 입금이거나, 같은 이름·금액 후보가 여러 개라면 자동확정하지 않습니다.

같은 이름의 사람이 두 명이라 자동매칭이 안 됩니다.

정상입니다. ClassRelay는 임의로 한 사람을 고르지 않고 확인필요로 둡니다. 신청자 상세에서 실제 입금을 확인해 수동으로 연결하세요.

Gmail 권한창이 다시 뜹니다.

ClassRelay는 Google Access Token을 영구 저장하지 않습니다. 토큰이 만료된 뒤 Google API 작업을 다시 할 때 권한창이 다시 열릴 수 있습니다.

`발송 확인 필요`가 표시됩니다.

브라우저는 실패 응답을 받았지만 Gmail이 이미 메일을 처리했을 가능성이 있는 상태입니다. 고객 또는 본인의 수신함을 확인한 뒤 재발송 여부를 결정하세요. 자동으로 다시 보내지 않는 것이 정상입니다.

브라우저를 바꾸니 신청자와 발송기록이 없습니다.

운영 데이터는 브라우저 IndexedDB에 저장됩니다. 기존 브라우저에서 백업 JSON을 내보낸 뒤 새 브라우저에서 백업 불러오기를 해야 합니다.

Google Cloud 설정을 강의마다 다시 해야 하나요?

아닙니다. Google Cloud 프로젝트와 OAuth Client ID는 보통 처음 한 번만 설정합니다. 새 강의에서는 ClassRelay에 강의를 추가하고 새 Google Form을 연결하면 됩니다.

조금 더 알고 싶은 분만

기술적인 내용은 운영을 익힌 뒤 읽어도 됩니다.

아래 내용은 ClassRelay를 사용하는 데 필수로 외울 필요가 없습니다.

왜 Client Secret을 입력하지 않나요?

ClassRelay는 Google Identity Services의 브라우저 Token Model을 사용합니다. Web Client ID와 사용자가 승인한 짧은 수명의 Access Token으로 Google API를 호출하며 Client Secret을 브라우저에 넣지 않습니다.

내 신청자와 은행 데이터는 어디에 저장되나요?

중앙 ClassRelay DB가 아니라 현재 브라우저의 IndexedDB에 저장됩니다. 은행 입금내역 파일도 브라우저에서 읽고 서버로 올리지 않습니다. 저장한 은행 내역 템플릿도 같은 브라우저에 저장됩니다. 그래서 백업이 중요합니다.

Gmail에서 어떤 권한을 사용하나요?

https://www.googleapis.com/auth/gmail.send를 사용합니다. 이 권한은 사용자를 대신해 메일을 보내는 용도입니다.

Google Form에서는 어떤 권한을 사용하나요?

Form 구조를 읽는 forms.body.readonly와 Form 응답을 읽는 forms.responses.readonly를 사용합니다.

Form 동기화는 내부적으로 어떻게 중복을 구분하나요?

Google Forms API의 forms.responses.list(formId)로 응답 목록을 확인하고 각 응답의 response ID를 사용해 기존 신청 건과 새 신청 건을 구분합니다. 이 설명은 운영을 위해 외울 필요는 없습니다.

YouTube 일부공개와 비공개는 어떻게 다른가요?

YouTube 공개 범위 공식 안내에 따르면 일부공개는 링크를 가진 사람이 볼 수 있고 다시 공유할 수 있습니다. 비공개는 허용한 사용자에게만 열립니다. ClassRelay는 YouTube 권한을 제어하지 않고 저장된 녹화본 URL을 메일로 전달합니다. YouTube 공개 범위 안내 ↗
