Local-first 데이터

운영 데이터는 사용자의 브라우저에 저장됩니다.

ClassRelay v2.9.0의 기본 배포 구조는 회원가입 및 중앙 애플리케이션 DB를 사용하지 않습니다. 강의별 히스토리는 하나의 로컬 IndexedDB 안에서 courseId로 분리되어 누적 저장됩니다.

저장되는 데이터

강의 정보, Google Form에서 동기화한 신청자 정보, CSV에서 가져온 입금 정보, 매칭 결과, 여러 이메일 템플릿, 성공 발송 당시 제목·본문·URL snapshot, 발송 로그, OAuth Client ID 설정이 IndexedDB에 저장될 수 있습니다.

서버로 보내지 않는 데이터

기본 정적 배포 구조에서는 은행 CSV 파일과 IndexedDB 운영 데이터를 별도 애플리케이션 DB로 업로드하는 서버 기능이 없습니다.

Google 권한

사용자가 만든 OAuth Client ID를 사용합니다. Google Access Token은 브라우저 메모리에서 API 요청에 사용하며 IndexedDB 백업에 저장하지 않습니다. Client Secret은 입력받지 않습니다.

백업 책임

브라우저 데이터는 사용자가 사이트 데이터 삭제, 브라우저 프로필 변경, 기기 변경 등을 하면 사라질 수 있습니다. 설정의 백업 내보내기를 통해 운영 데이터를 직접 보관해야 합니다.

Google로 전송되는 정보

Google Form 동기화와 Gmail 발송을 실행하면 사용자의 브라우저가 Google API에 직접 요청합니다. 해당 처리는 Google 계정 및 Google Cloud 프로젝트의 권한 설정을 따릅니다.

여러 탭 간 조정

같은 브라우저에서 ClassRelay를 여러 탭으로 열 경우 Web Locks, BroadcastChannel, localStorage 기반 잠금 정보를 사용해 쓰기 작업 충돌을 줄입니다. 이 조정 정보는 같은 사이트 origin의 브라우저 안에서만 사용되며 신청자 개인정보나 은행 CSV 원문을 외부 서버로 전송하지 않습니다.
